# End-to-End Heavy-Spam Validation Run — 2026-06-11

**Scope:** spam all 25 ingestion sources at 2× gate load, then follow the data through
every layer: webhook/Kafka ingress → normalizer → observation writer → embeddings →
think trigger queue → reasoning (T1–T4) → models/edges → product gateway endpoints.

**Verdict: the pipeline works end to end.** Real observations ingested under heavy
concurrent load became real semantic models served by the product gateway. Two genuine
defects were found in the reasoning/product layers (details in Findings).

## Findings

> **Update (same day):** Findings 1 and 2 are FIXED in the working tree —
> `sanitize_explicit_grammar_axes` + stance-default refill at the
> `construct_model` chokepoint (every insert path flows through it), and the
> history route now wraps `build_summary` in a transaction with the savepoint
> helper additionally guarding `is_in_transaction()`. Both verified empirically
> (the exact poisoned proposition inserts cleanly with on-enum values;
> `/v1/history/summary` returns 200 with real data) plus regression tests, and
> adversarially reviewed (2-lens panel, verdict: ship).

### 1. Memory-grammar enums unenforced between prompt and DB (96 failed runs)

`models.time_mode` / `models.modality` are constrained only in two places: the prompt
text (`services/reasoning/think/prompt.py:125` documents
`observed | inferred | expected | normative`) and the DB CHECKs
(`models_time_mode_valid`, `models_modality_valid`). Nothing in between validates them.
When the LLM emits an off-enum value (`time_mode="point_in_time"` ×63,
`modality="actual"` ×33 in this run), the value sails through ops validation and the
whole think run fails at the DB INSERT (`CheckViolationError`), then burns retry
attempts (max 5) until a re-roll picks a valid value.

- Severity: high under non-default models. With gpt-5.5 this was the **dominant failure
  mode** (~40% of attempted runs); deepseek-chat apparently picks valid values more
  often, which is why the real-LLM suite hasn't surfaced it.
- Cost impact this run: ~$0.95 of $1.72 total spend went to runs killed by this.
- Precise mechanism (found during the fix): the grammar columns are STORED
  GENERATED columns reading `proposition->>'<axis>'` (migration 0048). Python's
  `derive_memory_grammar` already ignored off-enum values, but the raw proposition
  JSONB was persisted verbatim and the generated columns extracted the bad value.
- **Fix applied:** `sanitize_explicit_grammar_axes` (lib/shared/memory_grammar.py)
  drops off-enum axis keys at the `construct_model` chokepoint, then
  `apply_stance_grammar_defaults` refills them with the kind defaults (needed
  because the `target_actor_id` generated column reads `proposition->>'claim_role'`
  directly). All insert paths flow through `construct_model`; the LLM-facing
  update path can't touch the proposition (review-verified).

### 2. `/v1/history/summary` 500s on every call — SAVEPOINT outside transaction

`services/product/history/router.py:112` acquires a bare pooled connection and passes
it to `build_summary`; `services/product/history/summary.py:199` then executes
`SAVEPOINT hist_summary_*`, which Postgres rejects outside a transaction block
(`NoActiveSQLTransactionError`) → unconditional 500.

- This was reportedly fixed in May (pre-re-layering); `git log -S is_in_transaction`
  shows no such fix ever existed on the current path — it was **lost in the
  `6e25453` re-layering**.
- **Fix applied:** both — the route wraps `build_summary` in `conn.transaction()`,
  and `_safe_fetchrow` skips the savepoint on bare connections
  (`is_in_transaction()` guard), with a bare-connection regression test.

### 3. Run-ops note: DeepSeek key exhausted (not a code bug)

The first drain wave failed 100%: DeepSeek returned
`402 Insufficient Balance`, the provider circuit breaker opened, and 159 runs
fast-failed with zero LLM calls. The breaker, retry bookkeeping, and
`--stale-lock-seconds` recovery all behaved correctly; after resetting trigger
attempts and switching to `LLM_PROVIDER=codex` (model auto-resolved to gpt-5.5,
app-server transport from `~/.codex/auth.json`), the same triggers drained cleanly.
**Action item: top up the DeepSeek balance or switch the default provider in `.env`.**
